## Warum semrel?

<CardGrid stagger>
  <Card title="Keine manuelle Versionierung" icon="approve-check">
    semrel analysiert deine [Conventional Commits](https://www.conventionalcommits.org/) und entscheidet automatisch, ob `major`, `minor` oder `patch` erhöht wird — ohne manuelles Eingreifen.
  </Card>
  <Card title="Vollständig plugin-basiert" icon="puzzle">
    Jeder Schritt der Pipeline ist ein austauschbares Plugin, das als Subprozess läuft. Ersetze GitHub durch GitLab, tausche den Changelog-Generator aus oder füge Slack-Benachrichtigungen hinzu — alles ohne Änderungen am Core.
  </Card>
  <Card title="Monorepo-fähig" icon="seti:folder">
    Versioniere mehrere unabhängige Module in einem Repository, jeweils mit eigener Tag-Serie und eigener Konfigurationsdatei.
  </Card>
  <Card title="Supply-Chain-Sicherheit" icon="shield">
    Signierte Releases mit Sigstore Cosign, CycloneDX/SPDX SBOM, SLSA Level 1 Provenance. DCO Sign-off und REUSE/SPDX-Compliance bei jedem PR.
  </Card>
  <Card title="Sprachunabhängige Plugins" icon="translate">
    Plugins sind einfache Binaries, die als Subprozess laufen — du kannst sie in Go, Python, Rust, Node.js oder jeder anderen Sprache schreiben.
  </Card>
  <Card title="Dry-run-Modus" icon="information">
    Vorher genau sehen, was semrel tun würde. `semrel release --dry-run` validiert die Konfiguration sicher, ohne etwas zu verändern.
  </Card>
  <Card title="Open Source" icon="open-book">
    Apache 2.0 lizenziert. Offen entwickelt auf [SemRels/semrel](https://github.com/SemRels/semrel).
  </Card>
</CardGrid>
