## Offizielle Plugins

Offizielle Plugins werden in der Organisation [SemRels](https://github.com/SemRels) veröffentlicht.

<CardGrid>
  <Card title="github" icon="github">
    **ProviderPlugin** für GitHub. Erstellt Releases, lädt Assets hoch und ruft die Commit-Historie über die GitHub-REST-API ab.
  </Card>
  <Card title="conventional-commits" icon="magnifier">
    **CommitAnalyzerPlugin**, das der Spezifikation [Conventional Commits](https://www.conventionalcommits.org/) folgt, um den Versions-Bump zu bestimmen.
  </Card>
  <Card title="markdown-changelog" icon="document">
    **ChangelogGeneratorPlugin**, das Release Notes als Markdown-Abschnitt `CHANGELOG.md` rendert.
  </Card>
  <Card title="go-mod-updater" icon="pencil">
    **FilesUpdaterPlugin**, das die nächste Version über mit `ldflags` kompatible Versionsvariablen in Go-Quelldateien schreibt.
  </Card>
  <Card title="packager-nfpm" icon="document">
    **PackagerPlugin**, das Linux-Pakete (`deb`, `rpm`, `apk`) mit `nfpm` baut.
  </Card>
  <Card title="publisher-oci" icon="open-book">
    **PublisherPlugin**, das Artefakte mit `oras push` in OCI-Registries hochlädt.
  </Card>
  <Card title="publisher-generic-http" icon="open-book">
    **PublisherPlugin**, das Artefakte zu benutzerdefinierten HTTP-Endpunkten hochlädt.
  </Card>
</CardGrid>

<Aside type="note">
  Alle offiziellen Plugins sind quelloffen und in der Organisation [SemRels](https://github.com/SemRels) verfügbar. Installiere jedes Plugin mit `semrel plugin install <name>`.
</Aside>

## Praktische Release-Ketten

### Go-Binaries + Paketartefakte + OCI-Publishing

```yaml
plugins:
  - uses: updater-go
    args:
      file: internal/version/version.go
      var_name: Version

  - uses: packager-nfpm
    args:
      config: packaging/nfpm.yaml
      target: dist/packages
      packagers: deb,rpm,apk

  - uses: publisher-oci
    args:
      ref: ghcr.io/semrels/myapp:{version}
      artifacts: dist/packages/myapp_amd64.deb,dist/packages/myapp_amd64.rpm
```

### Docker- oder Podman-Image-Workflow

```yaml
plugins:
  - uses: updater-docker
    args:
      file: Dockerfile
      arg_name: VERSION

  - uses: publisher-generic-http
    args:
      url: https://uploads.example.com/releases/{version}/{artifact}
      method: PUT
      token: ${UPLOAD_TOKEN}
      artifacts: dist/images/myapp-oci.tar
```

### Helm-Chart-Workflow

```yaml
plugins:
  - uses: updater-helm
    args:
      file: charts/myapp/Chart.yaml
      update_app_version: "true"

  - uses: publisher-oci
    args:
      ref: ghcr.io/semrels/charts/myapp:{version}
      artifacts: dist/charts/myapp-{version}.tgz
```

## Community-Plugins

Von der Community beigesteuerte Plugins werden im [semrel registry](https://registry.semrel.io/) aufgeführt, sobald es live ist. Wenn dein Plugin dort gelistet werden soll, öffne ein Issue oder einen PR im Haupt-Repository.
