semrel installiert Plugins als lokale Binärdateien und löst sie zur Laufzeit direkt auf — kein Daemon, kein globaler Zustand.
Das Plugin-Management-System stellt sicher, dass jedes Teammitglied und jeder CI-Runner exakt dieselbe Binary, in exakt derselben Version, verwendet.

## Ein Plugin installieren <Badge text="projektlokal" variant="tip" />

<Steps>

1. **Vollständige Registry-Referenz verwenden**

   Alle offiziellen Plugins gehören zum Namespace `@semrel`. Dieser muss immer angegeben werden:

   ```bash
   semrel plugin install @semrel/github
   ```

   Einen nackten Namen (`github`) akzeptiert semrel nur, wenn der Registry-Eintrag **keinen** Namespace hat.

2. **Bei Bedarf eine Version pinnen**

   ```bash
   semrel plugin install @semrel/github@1.2.0
   ```

3. **Die Lock-Datei committen**

   Eine Standard-Installation schreibt automatisch `.semrel.lock` im Repository-Root.
   Diese Datei zusammen mit `.semrel.yaml` committen, damit alle dieselbe Version verwenden.

</Steps>

<Aside type="caution" title="Namespace erforderlich">
  `semrel plugin install github` schlägt fehl, wenn das Plugin zum Namespace `@semrel` gehört:

  ```
  plugin "github" belongs to namespace @semrel — use:
    semrel plugin install @semrel/github
  ```

  Kategorie-Präfix-Namen wie `provider-github` oder `condition-github-actions` werden
  zu ihren kurzen Registry-Namen (`github`, `github-actions`) aufgelöst und unterliegen
  derselben Namespace-Regel.
</Aside>

### Benennung und Normalisierung

Alle Schreibweisen führen zur gleichen Binary auf der Festplatte — semrel entfernt Namespace, Version und Kategorie-Präfix, bevor es nach einer Binärdatei sucht:

| Config-Eintrag | Binary auf der Platte |
|---|---|
| `uses: github` | `semrel-plugin-github` |
| `uses: provider-github` | `semrel-plugin-github` |
| `uses: @semrel/github@1.2.0` | `semrel-plugin-github` |
| `uses: github-actions` | `semrel-plugin-github-actions` |
| `uses: condition-github-actions` | `semrel-plugin-github-actions` |

## Die Datei `.semrel.lock` <Badge text="neu" variant="success" />

`.semrel.lock` speichert die exakte Version und die veröffentlichten Prüfsummen jeder projektlokalen Plugin-Installation.
Die Datei wird automatisch aktualisiert, wenn `semrel plugin install` **ohne** `--plugin-dir` aufgerufen wird.

```json
{
  "semrelLockVersion": 1,
  "updatedAt": "2026-06-11T09:33:00Z",
  "plugins": [
    {
      "binaryName": "semrel-plugin-github",
      "ref": "@semrel/github",
      "version": "1.2.0",
      "checksums": {
        "linux_amd64":   "3b4c…",
        "linux_arm64":   "9f1e…",
        "darwin_amd64":  "c72a…",
        "darwin_arm64":  "55d0…",
        "windows_amd64": "a81b…",
        "windows_arm64": "e3f7…"
      }
    }
  ]
}
```

Prüfsummen werden für alle veröffentlichten Plattformen gespeichert, sodass `semrel plugin restore` die Binary auf jedem Betriebssystem und jeder Architektur ohne Registry-Abfrage verifizieren kann.

### Was committen, was ignorieren

<FileTree>
- .semrel.yaml        Konfiguration — **committen**
- **.semrel.lock**    gepinnte Plugin-Versionen — **committen**
- .semrel/
  - plugins/          Binary-Cache — ignoriert
  - registry-cache/   Metadaten-Cache — ignoriert
  - linux_amd64/      Download-Cache — ignoriert
  - darwin_arm64/     Download-Cache — ignoriert
  - windows_amd64/    Download-Cache — ignoriert
  - …
</FileTree>

Folgende Einträge in `.gitignore` aufnehmen:

```gitignore
# semrel — lokale Binärdateien und Caches (NICHT committen)
.semrel/plugins/
.semrel/registry-cache/
.semrel/linux_*/
.semrel/darwin_*/
.semrel/windows_*/
# .semrel.lock im Repo-Root wird committed
```

## `semrel plugin restore` <Badge text="neu" variant="success" />

`semrel plugin restore` liest `.semrel.lock`, lädt alle aufgeführten Plugins nach `.semrel/plugins/`,
überspringt bereits vorhandene Binärdateien und **verifiziert die Prüfsumme** für die aktuelle Plattform.

Dieses Kommando auf CI und nach dem Klonen eines Repositories ausführen:

<Tabs>
  <TabItem label="GitHub Actions">

  ```yaml
  jobs:
    release:
      runs-on: ubuntu-latest
      steps:
        - uses: actions/checkout@v4
        - name: semrel einrichten
          run: |
            curl -sSL https://semrel.io/install.sh | sh
        - name: semrel-Plugins wiederherstellen
          run: semrel plugin restore
        - name: Release
          run: semrel release
          env:
            SEMREL_PLUGIN_TOKEN: ${{ secrets.GITHUB_TOKEN }}
  ```

  </TabItem>
  <TabItem label="GitLab CI">

  ```yaml
  release:
    stage: release
    script:
      - semrel plugin restore
      - semrel release
    variables:
      SEMREL_PLUGIN_TOKEN: $CI_JOB_TOKEN
  ```

  </TabItem>
  <TabItem label="Gitea Actions">

  ```yaml
  jobs:
    release:
      runs-on: ubuntu-latest
      steps:
        - uses: actions/checkout@v4
        - name: semrel-Plugins wiederherstellen
          run: semrel plugin restore
        - name: Release
          run: semrel release
          env:
            SEMREL_PLUGIN_TOKEN: ${{ secrets.GITEA_TOKEN }}
  ```

  </TabItem>
</Tabs>

## `semrel plugin update`

Mit `semrel plugin update` hältst du gepinnte Plugin-Versionen aktuell.

```bash
# Nur prüfen (keine Installation)
semrel plugin update --check

# Alle gepinnten Plugins aus .semrel.lock aktualisieren
semrel plugin update

# Nur ein Plugin aktualisieren
semrel plugin update @semrel/github
```

Verhalten:

- Ohne Argumente liest semrel `.semrel.lock` und prüft jedes gepinnte Plugin gegen die neueste stabile Registry-Version.
- Mit `--check` zeigt semrel verfügbare Updates nur an.
- Ohne `--check` installiert semrel neuere Versionen und aktualisiert `.semrel.lock` automatisch.

## Plugin-Auflösungsreihenfolge

Beim Suchen nach einer Plugin-Binary prüft semrel diese Orte in dieser Reihenfolge:

<Steps>

1. **`path:` in `.semrel.yaml`** — explizite lokale Binary, höchste Priorität. Ideal für Entwicklung oder eigene Builds.

2. **`.semrel/plugins/<binary>`** — projektlokale Installation. Wird durch `semrel plugin install` und `semrel plugin restore` befüllt.

3. **`~/.semrel/plugins/<binary>`** — benutzerglobale Installation. Steht in allen Repositories auf der Maschine zur Verfügung.

4. **`$PATH`** — systemverwaltete Binary. Nützlich für Paketmanager-Installationen.

</Steps>

<Aside type="tip">
  Projektlokale Binärdateien (`.semrel/plugins/`) haben Vorrang vor dem benutzerglobalen Verzeichnis, sodass verschiedene Repositories unterschiedliche Plugin-Versionen pinnen können, ohne sich gegenseitig zu beeinflussen.
</Aside>

## Automatischer Plugin-Restore während `semrel release`

`semrel release` prüft die Plugin-Verfügbarkeit **vor allem anderen**.
Das genaue Verhalten hängt davon ab, ob `.semrel.lock` committed ist:

| Situation | Was semrel macht |
|---|---|
| Alle Plugins vorhanden | Sofort weitermachen — kein Download notwendig |
| Plugins fehlen + `.semrel.lock` vorhanden | **`semrel plugin restore` automatisch ausführen**, dann weitermachen |
| Plugins fehlen, kein Lock-File | Einzelnen Auto-Install versuchen (Best-Effort, neueste stabile Version) |

### Mit `.semrel.lock` (empfohlen)

```
$ semrel release
⬇  plugins missing — running semrel plugin restore from .semrel.lock…
✓  restored @semrel/github@1.2.0 → .semrel/plugins/semrel-plugin-github
✓  restored @semrel/github-actions@0.1.0 → .semrel/plugins/semrel-plugin-github-actions
Running condition checks…
```

Der Restore aus der Lock-Datei ist eine **harte Operation**: Wenn die Prüfsumme einer Binary nicht übereinstimmt, bricht semrel sofort ab, statt stillschweigend eine andere Binary zu verwenden.

### Ohne `.semrel.lock`

Ohne Lock-Datei versucht semrel, jedes fehlende Plugin einzeln zu installieren. Versions-Auflösung:

1. **Version aus `uses:`** — `uses: github@1.2.0` pinnt die Version explizit.
2. **Neueste stabile Version** — wenn keine Version angegeben ist, wird die neueste Nicht-Prerelease-Version geladen.

<Aside type="tip">
  `.semrel.lock` committen für reproduzierbare, auditierbare Plugin-Installationen.
  Ohne Lock-Datei holt sich `semrel release` auf einem frischen Rechner die gerade aktuelle Version — was sich im Laufe der Zeit ändern kann.
</Aside>

## Installation in ein anderes Verzeichnis

Mit `--plugin-dir` in ein anderes Verzeichnis als `.semrel/plugins/` installieren:

```bash
# Benutzerglobale Installation (aktualisiert .semrel.lock NICHT)
semrel plugin install @semrel/github --plugin-dir ~/.semrel/plugins

# Eigener Pfad
semrel plugin install @semrel/github --plugin-dir /opt/semrel/plugins
```

<Aside type="caution">
  Die Installation mit `--plugin-dir` aktualisiert `.semrel.lock` **nicht**. Nur Standard-projektlokale Installationen werden in der Lock-Datei erfasst.
</Aside>
