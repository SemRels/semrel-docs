The semrel-registry exposes a public JSON REST API for discovering and downloading semrel plugins.
The base URL for the official registry is `https://registry.semrel.io`.

<Aside type="note">
  Most read operations are public and require no authentication.
  Plugin submission requires a GitHub account (OAuth).
  Administrative operations are not documented here.
</Aside>

---

## Plugin discovery

### `GET /plugins.json`

Returns the complete plugin catalogue as a JSON document — this is the primary endpoint consumed by the `semrel` CLI.

```bash
# Default registry
curl https://registry.semrel.io/plugins.json

# Custom registry (set via SEMREL_REGISTRY_URL)
curl $SEMREL_REGISTRY_URL/plugins.json
```

The response format is documented in the [plugin metadata schema](https://registry.semrel.io/schemas/plugin-metadata.json).

---

### `GET /api/v1/plugins`

Lists plugins with pagination and filtering.

**Query parameters**

| Parameter | Type | Default | Description |
|---|---|---|---|
| `page` | integer | `1` | Page number |
| `limit` | integer | `20` | Results per page (max 100) |
| `category` | string | — | Filter by category (`analyzer`, `generator`, `provider`, `condition`, `hook`, `updater`, `packager`, `publisher`) |
| `search` | string | — | Full-text search across name, description, and tags |

**Response**

```json
{
  "plugins": [
    {
      "namespace": "@semrel",
      "name": "github",
      "description": "Publishes GitHub releases and uploads assets.",
      "category": "provider",
      "repository": "https://github.com/SemRels/provider-github",
      "license": "Apache-2.0",
      "tags": ["github", "release"],
      "latestVersion": "1.2.0",
      "downloads": 4891
    }
  ],
  "total": 27,
  "page": 1,
  "limit": 20
}
```

### `GET /api/v1/plugins/@:namespace/:name`

Returns a plugin by namespace and name.

```bash
curl https://registry.semrel.io/api/v1/plugins/@semrel/provider-github
```

### `GET /api/v1/plugins/:id/versions`

Lists all published versions of a plugin.

```json
[
  {
    "version": "1.2.0",
    "changelog": "## 1.2.0\n\n- Added asset upload support",
    "downloadUrl": "https://github.com/SemRels/provider-github/releases/download/v1.2.0/plugin-linux-amd64",
    "checksums": {
      "linux_amd64": "3b4cde…"
    },
    "prerelease": false,
    "downloads": 1240,
    "createdAt": "2024-03-20T14:30:00Z"
  }
]
```

### `GET /api/v1/plugins/:id/versions/:version/downloads` <Badge text="POST" variant="note" />

Records a download event. Called automatically by `semrel plugin install` — no manual use needed.

## Plugin submission

Plugin authors can submit a community plugin for review:

### `POST /api/v1/plugins/submit` <Badge text="Requires Auth" variant="caution" />

Submits a plugin for review. The plugin is published with `status: pending` until approved.

**Request body**

```json
{
  "name": "my-analyzer",
  "description": "A custom commit analyzer.",
  "category": "analyzer",
  "repository": "https://github.com/you/my-analyzer",
  "license": "Apache-2.0",
  "tags": ["analyzer"]
}
```

Authentication uses GitHub OAuth — browse to `https://registry.semrel.io` and sign in before submitting.

## Webhook (for plugin release workflows)

### `POST /api/v1/webhooks/release`

Plugin release workflows call this endpoint to notify the registry of a new version. Add this step to your plugin's release workflow:

```yaml
- name: Notify semrel registry
  run: |
    curl -s -X POST https://registry.semrel.io/api/v1/webhooks/release \
      -H "Content-Type: application/json" \
      -H "X-Webhook-Secret: ${{ secrets.REGISTRY_WEBHOOK_SECRET }}" \
      -d '{
        "action": "release",
        "plugin": {
          "name": "my-plugin",
          "namespace": "@semrel",
          "version": "${{ steps.semrel.outputs.SEMREL_VERSION }}",
          "repository": "https://github.com/${{ github.repository }}"
        }
      }'
```

The webhook secret is provided to plugin maintainers separately. See the [plugin publishing guide](/plugins/publishing/) for the full release workflow.

## Schema endpoints

### `GET /schemas/core/v1.json`

Returns the [JSON Schema](https://registry.semrel.io/schemas/core/v1.json) for `.semrel.yaml`. Use with any LSP-aware editor for inline validation:

```yaml
# yaml-language-server: $schema=https://registry.semrel.io/schemas/core/v1.json
```

### `GET /schemas/plugins/{name}/v1.json`

Returns the JSON Schema for a specific plugin's `args:` configuration. Use the
canonical registry name, such as `provider-github` or `hook-slack`.

### `GET /schemas/plugins/{name}/latest.json`

Redirects (HTTP 301) to the most recent schema version for the named plugin.

## Rate limiting

Public endpoints are rate-limited per client IP:

| Endpoint group | Limit |
|---|---|
| Plugin read endpoints | 60 req/min |
| `/plugins.json` | 10 req/min |
| OAuth endpoints | 20 req/min |

Responses exceeding the limit return `HTTP 429 Too Many Requests` with a `Retry-After: 60` header.

## Self-hosting

The registry is open source. To run your own instance, see the [semrel-registry](https://github.com/SemRels/semrel-registry) repository. Point the CLI at your instance by setting `SEMREL_REGISTRY_URL`.
