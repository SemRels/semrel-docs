This guide targets teams currently using semantic-release and migrating to semrel.

## Mapping at a glance

| semantic-release concern | semrel equivalent |
| --- | --- |
| Commit analyzer plugins | `@semrel/analyzer-conventional` or `@semrel/analyzer-default` |
| Release notes/changelog plugins | `@semrel/generator-release-notes`, `@semrel/generator-changelog-md`, `@semrel/generator-changelog-html` |
| `@semantic-release/npm` | `@semrel/updater-npm` (`pre-tag`) + `@semrel/publisher-npm` (`release`) |
| `@semantic-release/exec` | `@semrel/hook-exec` (supports `verifyConditionsCmd`, `prepareCmd`, `publishCmd`, `successCmd`) |
| Generic regex/version file replacements | `@semrel/updater-replace` (`pre-tag`) |
| Crates / PyPI / Docker / OCI publishing | `@semrel/publisher-crates`, `@semrel/publisher-pypi`, `@semrel/publisher-docker`, `@semrel/publisher-oci`, `@semrel/publisher-generic-http` |

## Recommended rollout

<Steps>

1. Keep your existing branch and trigger policy unchanged.
2. Add semrel in dry-run mode and compare computed version + notes with semantic-release output.
3. Switch changelog/release note generation to semrel generators.
4. Switch publishing from semantic-release plugins to semrel publishers.
5. Disable semantic-release tagging/publishing after one stable release cycle.

</Steps>

## Typical semrel baseline

```yaml
plugins:
  - uses: @semrel/provider-github

  - uses: @semrel/analyzer-conventional

  - uses: @semrel/generator-release-notes

  - uses: @semrel/generator-changelog-md
    args:
      file: CHANGELOG.md
```

## Publishing replacement examples

- npm package flow: keep `npm publish` in CI after semrel determines version and changelog.
- GitHub release assets: use your CI upload step or plugin-based publishing.
- OCI/image or generic artifacts: use `@semrel/publisher-oci` or `@semrel/publisher-generic-http`.

<Aside type="tip">
  If you used semantic-release channels like `next` and `beta`, keep them as branch-specific semrel configs and avoid cross-branch tag ownership.
</Aside>

## Risks and checks

- Ensure only one system creates tags.
- Compare at least 10 recent commits in dry-run to validate version parity.
- Move credentials to `SEMREL_PLUGIN_*` environment variables.
